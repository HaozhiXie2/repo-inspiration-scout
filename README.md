# Repo Inspiration Scout

一个用于新项目构思阶段的 Codex Skill：把模糊的产品想法转化为可验证的 GitHub 调研，并筛选三个最值得借鉴的开源参考项目。

## 为什么做

直接搜索“类似项目”容易得到高 Star 但不匹配的仓库，也容易把搜索摘要当成事实。本 Skill 将关键词拆解、候选筛选、README 核验、维护状态判断和许可证提醒固化为标准流程，使调研结论更可追溯。

## 能做什么

- 将项目想法拆分为多组检索关键词；
- 从公开 GitHub 仓库中筛选高匹配度候选；
- 阅读 README 和必要的项目文件验证关键功能；
- 用中文提供功能、技术栈、维护情况、许可证、风险与借鉴建议；
- 在候选不足或证据不足时明确说明限制，不用低质量仓库凑数。

## 工作流程

```text
理解目标用户与核心任务
-> 拆解 3-6 组检索词
-> 收集并淘汰低质量候选
-> 阅读 README 与必要项目文件
-> 按匹配度、维护情况、证据和复用风险排序
-> 输出 3 个推荐项目及采用建议
```

## 关键设计决策

- 不把 Star 数作为首要判断，优先评估目标用户和核心流程的匹配度。
- 不依赖搜索摘要，关键结论必须能追溯到仓库、README、许可证或 GitHub 元数据。
- 排除归档仓库、纯 fork、清单仓库和缺少实质实现的 Demo。
- 找不到三个可信候选时如实报告缺口，不用低质量结果凑数。
- 明确区分“值得借鉴”和“可以直接复用”，单独提示许可证及商业使用风险。

## 安装

将本仓库中的 `SKILL.md` 放入个人 Codex 技能目录：

```text
<CODEX_HOME>/skills/github-project-scout/SKILL.md
```

之后在 Codex 中明确调用 `github-project-scout`，或提出“找类似 GitHub 项目”“项目调研”“竞品开源参考”。

## 使用示例

```text
使用 github-project-scout：我想做一个面向独立开发者的 SaaS，自动收集用户反馈、归类问题并生成产品迭代建议。Web 优先，允许 Python 或 TypeScript。
```

Skill 会先在必要时询问关键约束，再返回三个带链接的参考项目和采用建议。

## 输出内容

每个入选项目包含匹配理由、核心功能、技术栈、维护情况、许可证、可借鉴点及不适用风险，并在结尾给出组合采用建议和调研置信度。

## 如何评估效果

- 对同一个项目构想重复运行，检查推荐结果与判断依据是否稳定；
- 人工抽查关键结论能否在 README 或仓库文件中找到证据；
- 记录候选数量、淘汰原因和最终推荐被实际采用的比例；
- 邀请 3-5 位目标用户对“相关性、可信度、决策帮助”进行 5 分制评分。

## 注意

结果仅用于调研与借鉴。使用、修改或分发任何项目代码前，请自行核验相应许可证条款。
